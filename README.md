Project Context: Cognitive Parsing Engine (BCI Integration)1. Project OverviewWe are building a Brain-Computer Interface (BCI) application that translates raw human brainwaves (EEG) into digital commands. The data science and machine learning pipeline is fully complete. My current goal is to build the software engineering bridge: connecting the Python/Machine Learning backend to a JavaScript frontend using FastAPI and WebSockets for real-time telemetry.2. The Machine Learning Engine (Current State)Data Shape: The input data is a 3D NumPy array representing a 4.0-second EEG recording at 160Hz. The exact tensor shape required for inference is (1, 64, 641) -> (Batch, Channels, Time_Steps).Preprocessing: Before inference, the raw data undergoes strict per-epoch Z-score normalization along the time axis (axis=-1) to prevent gradient saturation.The Model: We are using a Subject-Specific Enhanced EEGNet model (depthwise and separable convolutions).Inference Tech: PyTorch is stripped out. The model is exported to hybrid_eegnet.onnx. Inference is handled entirely on the CPU using the onnxruntime Python library for maximum speed and minimal dependencies.Output: The model outputs a probability array. Currently, it performs binary classification (0 = Left Hand, 1 = Right Hand) with 91.11% accuracy, but the architecture is ready to scale to 4 classes.3. The Integration Objective (What I need you to write)I need to transition from a local Python script to a client-server architecture. Please help me write the code for the following pipeline:Task A: FastAPI Server Setup: Create a Python FastAPI server. On startup, it must load the hybrid_eegnet.onnx model into an onnxruntime.InferenceSession so it stays in memory.Task B: WebSocket Route: Implement a WebSocket endpoint (/ws/bci-stream). Standard REST is too slow for BCI; we need persistent bidirectional communication.  Task C: Inference Execution: When the backend receives a trigger message via WebSocket, it should simulate a live stream by loading a sample (64, 641) array from a local .npy test file, applying Z-score normalization, passing it through the ONNX session, and extracting the predicted class and confidence score.Task D: Payload Delivery: Push the result back to the frontend immediately via the WebSocket in a JSON format (e.g., {"intent": "LEFT", "confidence": 0.94, "timestamp": 123456789}).Task E: Frontend Client (Vanilla JS): Write the client-side JavaScript to establish the WebSocket connection, send a "trigger" message when an HTML button is clicked, parse the returning JSON payload, and dynamically update a DOM element (like moving a cursor left or right on the screen) based on the intent.  4. ConstraintsKeep the Python backend strictly async where possible, using fastapi and websockets.Ensure the ONNX model is not re-loaded on every request (load it globally or via lifespan events).  No heavy frontend frameworks (React/Vue) for now; use Vanilla JS, HTML, and CSS for the UI proof-of-concept.
